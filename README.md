# DnD Companion

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/Shked235/DnD-Companion)

Веб-приложение для Dungeons & Dragons 5e (правила 2024), объединяющее три вещи:

1. **Лист персонажа** — конструктор и рабочий лист с автоматическими расчётами.
2. **Игровая комната** — виртуальный стол с картой, токенами, инициативой и общим чатом.
3. **Справочник 2024** — каталог правил, классов, видов, заклинаний, снаряжения и бестиария.

Интерфейс и данные — на русском. Две темы на одной коричневой палитре
(`#582F0E · #7F4F24 · #936639 · #A68A64`): тёмная и светлая, переключатель — в шапке.
Всё работает локально: без аккаунтов, подписок и облака.

---

## Быстрый старт

```bash
npm install
npm run dev
```

- клиент: `http://localhost:5173`
- сервер комнат: `http://localhost:8787`

Для игры с другими компьютерами в одной сети откройте адрес машины, где запущен сервер:
`http://192.168.0.8:5173` (dev) или `http://192.168.0.8:8787` после сборки.
`192.168.0.8` — это IP вашего компьютера в локальной сети; приложение показывает его на странице
«Комнаты», а вручную его можно узнать командой `ipconfig` (Windows) или `ip a` (Linux/macOS).

Продакшен-режим:

```bash
npm run build
npm start        # http://localhost:8787
```

## Модули

### Лист персонажа

- Конструктор: вид, класс, предыстория, уровень 1–20, характеристики (стандартный набор,
  покупка за 27 очков, бросок 4d6, вручную), прибавки предыстории (+2/+1 или +1/+1/+1),
  навыки класса и предыстории, стартовый набор класса.
- Автоматически считаются: модификаторы и спасброски, бонус владения, навыки и пассивная
  Внимательность, КД (с учётом типа доспеха, ограничения Ловкости и щита), хиты и кости хитов,
  инициатива, скорость, СЛ и бонус атаки заклинаний, ячейки (полный/полузаклинатель/колдун),
  атаки из надетого оружия (фехтовальное, дальнобойное, мастерство), грузоподъёмность и вес.
- Броски d20 (клик по навыку, спасброску, атаке) с преимуществом/помехой, урон по формуле,
  журнал бросков, быстрые кубики.
- Хиты: урон, лечение, временные хиты, спасброски от смерти, состояния и истощение.
- Отдых: короткий (трата костей хитов) и длинный (полное восстановление хитов, всех костей
  хитов и ячеек). Повышение уровня с автоматической выдачей умений класса.
- Тонкая настройка: ручной КД, скорость и бонус инициативы (бездоспешная защита, предметы,
  особенности подкласса).
- Экспорт/импорт JSON, печатная версия (A4, светлая тема).
- Импорт персонажа из **Long Story Short**: по ссылке на публичный лист или из JSON-файла
  конструктора. Переносятся характеристики, класс, вид, предыстория, навыки, хиты, КД,
  скорость, оружие (узнаётся по справочнику), монеты и умения текстом.

### Игровая комната

- Создание комнаты с кодом (5 символов) и ключом Мастера; вход по коду.
- Роли: Мастер и игрок. Мастер ведёт карту, токены, инициативу и хендауты; игрок двигает
  только своего персонажа.
- Карта: загрузка изображения (сжатие до 2000 px), панорама, зум, сетка, линейка расстояний
  (5 футов за клетку, диагонали считаются как клетка — правило 2024).
- Токены: имя, хиты, полоса здоровья, цвет стороны, перетаскивание, удаление.
- Трекер инициативы: автоматический сбор участников, бросок d20 + модификатор, раунды и ходы.
- Чат с общим логом бросков, команда `/r 2d6+3`, кубики d4–d100.
- Хендауты (только Мастер) и привязка листа персонажа к комнате: Мастер видит КД, хиты, атаки
  и заклинания игроков.
- Панель **Vortex**: Мастер вставляет ссылку на свою комнату `vortex.longstoryshort.app`,
  остальные открывают её одной кнопкой.
- Состояние комнат хранится на сервере в `server/data/rooms.json` и переживает перезапуск.

### Справочник

Разделы: классы (12), виды (10), предыстории (16), черты (47), заклинания (85), снаряжение (75),
магические предметы (18), бестиарий (24), состояния (15), правила (37). Всего ~339 записей.

- Полнотекстовый поиск по названию (рус/англ), описанию и тегам.
- Фильтры: уровень/школа/класс для заклинаний, тип для снаряжения, редкость для предметов,
  CR для бестиария.
- Карточки со структурными полями и перекрёстными ссылками (заклинание → класс, предыстория →
  черта, умения класса по уровням, блок характеристики монстра).

### Radmin VPN

Если компьютеры не в одной локальной сети, проще всего соединить их через Radmin VPN:

1. Установите Radmin VPN на компьютер Мастера и на компьютер игрока.
2. Мастер: «Сеть» → «Создать сеть», задайте имя и пароль сети.
3. Игрок: «Сеть» → «Присоединиться к сети», введите то же имя и пароль.
4. Мастер запускает приложение (`npm start` или `npm run dev`) и разрешает Node.js в брандмауэре Windows.
5. Игрок открывает `http://<Radmin-IP Мастера>:8787` — IP виден в окне Radmin VPN и в приложении
   на странице «Комнаты» (в dev-режиме порт 5173).
6. Мастер создаёт комнату и передаёт код; игрок вводит его в «Комнаты» → «Войти по коду».

### Сохранение состояния

- Листы персонажей и профиль игрока хранятся в `localStorage` браузера и сохраняются сразу.
- Черновик конструктора персонажа пишется автоматически: страницу можно обновить и продолжить.
  Кнопка «Сбросить» очищает черновик.
- Состояние комнаты (карта, токены, инициатива, чат, хендауты) хранится на сервере в
  `server/data/rooms.json` и переживает перезапуск.
- Для каждой комнаты в браузере запоминаются привязанный персонаж и открытая вкладка
  (чат / хендауты / лист), поэтому после F5 всё возвращается на место.

## Интеграции

### Long Story Short (персонажи)

Два способа:

1. **По ссылке** — «Персонажи» → «Из Long Story Short» → вставьте адрес вида
   `https://longstoryshort.app/characters/elf-bard/`. Сервер забирает публичный
   `page-data.json` персонажа, клиент раскладывает его в наш лист.
2. **Файлом** — кнопка «Импорт» принимает JSON персонажа LSS (`jsonType: "character"`),
   JSON их страницы и наш собственный экспорт.

Что переносится: имя, класс, уровень, вид, предыстория, характеристики, владения навыками,
хиты, КД, скорость, оружие (сопоставляется со справочником), монеты, умения и снаряжение
текстом. Что не переносится: список заклинаний (в LSS-файле его нет, только ячейки) и
полные тексты — они остаются в заметках. Предупреждения показываются до импорта.

Важно: листы LSS собраны по правилам **2014**, наш движок считает по **2024**. После импорта
фиксируются КД/хиты из файла, а дальше расчёты идут по 2024 — проверьте вид и предысторию.

### Лист персонажа LSS (броски в чат)

Официальное встраивание: SDK `@longstoryshort/vtt-sdk` (MIT) и iframe
`https://longstoryshort.app/iframe/characters/list/`. Лист присылает событие `lss:roll`,
приложение пересылает его в чат комнаты.

В комнате: вкладка «Лист» → «Открыть лист LSS». Броски из листа появляются в общем чате
у всех участников.

Важное ограничение: LSS разрешает встраивание только доменам из белого списка. `localhost` и
локальные IP туда добавить нельзя, поэтому локально вместо iframe показывается инструкция.
Разверните приложение на домене и попросите добавить его: `@shakusky` в Telegram,
`shakusky.lss` в Discord или в сообщения сообщества VK. После этого лист загрузится внутри
комнаты, а его броски пойдут в чат.

### Vortex (комнаты)

Vortex — закрытый виртуальный стол: комната создаётся и живёт на их сервере, вход требует
авторизации, `/room/` отдаёт 403 без сессии, а `Content-Security-Policy: frame-ancestors`
разрешает встраивание только доменам из их списка. Поэтому приложение не подключается к
чужой комнате по сети и не подменяет её протокол, а делает безопасную часть интеграции:
Мастер сохраняет ссылку на комнату Vortex, все участники открывают её в новой вкладке.

Кнопка «Лог бросков Vortex» открывает `/room/<id>/logger/` отдельным окном: так кубики Vortex
видны рядом с приложением, но в наш чат автоматически не попадают. Публичного API и
универсальных вебхуков у Vortex нет — только уведомления в Telegram/Discord и интеграция с
Owlbear Rodeo. Для настоящей синхронизации бросков нужен официальный API Vortex или
разрешение его команды.

## Структура

```
server/          Node + ws: HTTP API, WebSocket комнат, раздача dist
scripts/         dev.mjs (клиент+сервер), smoke.mjs (интеграционный прогон комнаты)
src/data/        типы и контент справочника (TS-модули)
src/lib/rules/   движок 5e 2024 + тесты
src/lib/import/  импорт персонажей Long Story Short
src/lib/         store, комнаты (WS-клиент), файлы, UI-примитивы
src/pages/       главная, персонажи, конструктор, лист, справочник, комнаты
src/styles/      токены тёмной/светлой темы и компоненты
```

## Проверки

```bash
npm run typecheck   # tsc --noEmit
npm test            # vitest: 16 тестов движка
npm run build       # typecheck + production-сборка
npm run smoke       # интеграционный прогон комнаты (нужен запущенный сервер)
```

`npm run smoke` создаёт комнату, подключает Мастера и игрока по WebSocket и проверяет роли,
права на токены, чат, броски, хендауты, инициативу, синхронизацию карты и передачу листа.

## Правила и данные

- Механика соответствует **D&D 5e (2024)** и открытому **SRD 5.2 (CC BY 4.0)**.
- Тексты в справочнике — краткие авторские формулировки механики (кости, спасброски, дистанции,
  эффекты), а не перепечатка книг. Полные описания и таблицы остаются в PHB/DMG.
- Репозиторий TTG-Club/dnd5e-2024 использован только как ориентир по структуре полей: у него
  нет открытой лицензии (`private: true`), поэтому его тексты и данные не копировались.
- Если нужен другой набор контента, добавьте объект в соответствующий файл `src/data/*.ts` —
  типы и поиск подхватят его автоматически.

## Ограничения

- Мультикласс поддержан в модели данных, но в интерфейсе v1 — один класс.
- Заклинания: 85 из ~400 (ядро по всем уровням и классам), тексты краткие.
- Автоматика заклинаний ограничена броском урона/лечения; эффекты вроде «схваченный» или
  «ослеплённый» отмечаются вручную в состояниях.
- Магические предметы и черты не применяются к расчётам автоматически (кроме ручных
  переопределений КД/скорости и поля «прибавка к максимуму хитов» в данных персонажа).
- Нет аккаунтов, паролей и публичного хостинга: комнаты защищены только кодом и ключом Мастера.
  Не выставляйте сервер в интернет без reverse-proxy и аутентификации.
- Изображения карт и аватары хранятся как data URL в состоянии комнаты; очень большие файлы
  отклоняются сервером.
